# ResearchFlow — 研究生智慧工作排程系統（Pixel Art 版）規格書

## 1. 專案背景與目的
研究生需要同時管理論文研究、課程作業、研究計畫與其他雜務，不同任務具有不同期限、重要性與預估工時。開發 ResearchFlow 將任務集中在同一頁，利用規則式優先排序和完成率統計，協助判斷先做什麼並降低漏做風險。

## 2. 使用者與使用情境
對象：碩博士生、進行專題的學生。情境：每天查看待辦、加入教授交辦事項、更新任務狀態、查看完成率；發表或繳交時可載入示範資料快速操作。

## 3. 設計風格
使用 Pixel Art／8-bit 復古遊戲視覺。採深色夜空背景、像素風邊框與硬陰影、方角按鈕、點陣感進度條、角色插畫（純 CSS 繪製）。支援亮色切換與手機排版，無需外部圖片或 assets 目錄。

## 4. 資料欄位
- id：任務唯一識別碼（自動產生）
- title：任務名稱，必填，最多 70 字元
- category：論文研究／課程作業／研究計畫／其他
- priority：高／中／低
- due：截止日期，必填（YYYY-MM-DD）
- hours：預估工時，0.5–999 小時，0.5 小時為輸入級距
- status：待處理／進行中／已完成
- note：備註，最多 400 字元
- created：建立時間（自動產生）

## 5. 功能規格
F01 新增任務：輸入資料並送出；驗證名稱、日期及工時。
F02 編輯與刪除：保留同一任務識別碼與建立時間；刪除前確認。
F03 更新狀態：一鍵循環待處理→進行中→已完成→待處理。
F04 搜尋與篩選：可依任務名稱、備註搜尋；依類別與狀態篩選。
F05 排序：智慧優先（預設）、截止日最近、最新建立。
F06 統計：總任務數、已完成數、三天內到期（含逾期）未完成數、完成率。
F07 圖表：以長條顯示各類別任務數占全部任務的百分比。
F08 儲存：使用 localStorage，刷新網頁資料仍存在；不會跨瀏覽器或裝置同步。
F09 示範：首次進入自動產生四筆示範資料；可按鈕重新載入範例並覆蓋現有任務（有確認提示）。
F10 清空資料：需確認後才清空；資料清空後刷新維持空白。
F11 深／亮色切換：儲存所選主題。
F12 響應式：手機與桌面排版調整；原生 dialog 表單可鍵盤操作。

## 6. 優先分數規則
只對未完成任務計算：重要程度（高 40、中 25、低 10）＋截止期限加分（逾期 45、0–1 天 35、2–3 天 28、4–7 天 18、8–14 天 8、15 天以上 0）＋工時加分（≤2 小時 5、>2 且 ≤4 小時 3、>4 小時 0）。
預設排序：未完成任務優先，分數由高到低，同分者截止日期較近優先；已完成任務置底。本機日期以使用者裝置為準。屬可解釋的規則式排序，不宣稱使用機器學習或遠端 AI。

## 7. 頁面架構
頂端標題與主題切換 → 像素角色主視覺 → 統計卡片 → 任務清單與搜尋篩選 → 類別圖表／使用說明 → 任務輸入對話框 → 頁尾。

## 8. 技術與限制
HTML5 結構、CSS3 響應式像素風、原生 JavaScript 操作 DOM；無框架、無外部 API／後端。分開開發時使用 index_source.html、style.css、script.js；發布 GitHub Pages 用完整嵌入 CSS/JS 的單一 index.html。localStorage 容量與保存受瀏覽器設定影響；跨裝置不會同步。

## 9. 驗收測試
1. 新增任務後總數加 1；重新整理仍存在。
2. 編輯後任務內容正確改變且數量不變。
3. 完成任務後已完成數／完成率同步更新，智慧排序移至未完成任務之後。
4. 截止日、重要程度、工時改變時，優先分數會更新。
5. 搜尋、類別／狀態篩選及三種排序功能可運作。
6. 刪除／清空前有確認；完成後數據和圖表更新。
7. 示範任務可重新載入，深亮色切換可保留。
8. 在手機窄螢幕與桌面瀏覽器檢查排列與按鈕。
9. GitHub Pages 根目錄有 index.html，公開網址可開啟且無需額外資源。

## 10. Vibe Coding 調整歷程（建議依實際操作紀錄修訂）
第一版定義研究生排程需求；第二版將一般儀表板改為 Pixel Art 視覺；第三版加入規則式優先分數、LocalStorage、範例任務與二次確認，以兼顧展示性與操作完整度。最終仍應記錄自己的實際測試與修正結果。
